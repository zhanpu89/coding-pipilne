# .opencode/ —— 你的项目资产

本目录由 coding-pipeline（一个**通用且专业**的软件工程编排器）安装而来。安装完成后，它**整体属于当前项目**，不再是外部强加的工具配置。

## 你可以做什么

- **改写 `rules/`**：6 份通用方法论规则（编码纪律 / 架构思考 / 精准定位 / 端锁定 / 文档对齐 / JSON 写入安全）是跨项目成立的专家标准。直接改写为团队 / 项目专属规范即可。
- **改写 `skills/` 资源**：各角色（需求 / 架构 / 详设 / 编码 / 评审 / 测试）的参考弹药是通用方法论，可按本项目技术栈与约定特化。
- **沉淀 `doc/` 资产**：用 skills 产出的 `doc/prd`、`doc/arch`、`doc/detailed`、`doc/tester` 是项目架构与规范的权威来源，由你持续优化。
- **调整 `opencode.json`**：如需开关某条规则，编辑本项目 `opencode.json` 的 `instructions` 即可。

## 设计原则（一句话）

工具的「分发态」保持**通用且专业、项目无关**；「资产态」由项目自己决定并演化——工具即你项目的专业开发人员。完整说明见工具的 `doc/DESIGN-PRINCIPLES.md`。
